For each subcategory we looked only at the **first/default example** (not the full style-variant list — several of these have 4–21 variants) with the code-language selector on **React** (it defaults to React on every one of these pages, so no switch was needed). No component source is pasted below — re-fetch the real code from Tailwind Plus (logged-in subscription) when actually vendoring.

Offline-safety check is against the rule in [`app-template/src/ui/blocks/README.md`](../../app-template/src/ui/blocks/README.md): drop `dark:` variants, remap `indigo`/`gray` literals to this app's theme tokens, and replace any external image/asset URL. Package check is against `app-template/package.json`, which already has `@headlessui/react@2.2.10` and `@heroicons/react@2.2.0` and nothing else UI-related.

## Notes on packages

Every one of the 10 stays within `@headlessui/react` + `@heroicons/react`, which are already dependencies — **no new npm packages needed** for any of them. Only #10 (Comboboxes) and #1 (Form Layouts, via its cover-photo icon and select chevron) actually reach for Headless UI or Heroicons; the rest (#2, #3, #5, #6, #8, #9) are plain HTML/CSS with zero imports, and #3/#6 use only a heroicon, no Headless UI.

## Notes on external/offline-unsafe assets

Only **#4 Sign-in and Registration** references an external URL (`tailwindcss.com/plus-assets/img/logos/mark.svg`, ×2 for light/dark). Everything else in this batch uses either no imagery or inline SVG/heroicon placeholders — no Unsplash photos turned up in any of the 10 first-examples looked at.

## Fit against the kernel `Field.tsx` primitive

`app-template/src/ui/Field.tsx` renders one accessible control per declared field type: `text | longtext | number | date | select | boolean`.

- **Direct 1:1 matches already covered by `Field.tsx`:** Input Groups ("Input with label") ≈ `type: "text"`; Textareas ("Simple") ≈ `type: "longtext"`; Select Menus ("Simple native") ≈ `type: "select"` (Tailwind Plus's version adds a `ChevronDownIcon` overlay that `Field.tsx` currently lacks — a candidate for a small heroicons-based polish since the package is already installed).
- **Same semantics, alternate skin:** Toggles ("Simple toggle") is a drop-in visual alternative for `type: "boolean"` — same single on/off checkbox underneath, just switch-styled instead of a checkbox square. Low-risk enhancement, no new field type needed.
- **Would need a new `FieldSpec` type (not representable today):** Radio Groups (single-select-from-a-short-list, an alternative to `select` for ≤3–5 options) and Checkboxes ("List with description", a **multi**-select list) both fall outside the current `text/longtext/number/date/select/boolean` union — `Field.tsx` only ever renders one control, and a checkbox *group* is structurally a list of controls bound to one array value. Comboboxes (searchable/filterable select) is a further-out candidate for when a `select` field's option list gets long.
- **Not field primitives at all — page/layout patterns instead:** Form Layouts ("Stacked") is a whole settings page composed from several `Field`-like controls plus custom sections (avatar upload, cover-photo dropzone) that have no `FieldSpec` equivalent; Sign-in and Registration is a full auth screen; Action Panels is a settings-card/CTA wrapper. These three are better candidates for the `src/ui/blocks/` showcase-page pattern (like the existing `home-screen-sidebar` entry) than for `Field.tsx`.
